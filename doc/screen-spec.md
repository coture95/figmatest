# screen-spec.md — 화면 명세

기준: doc/screens.md를 원본으로 하고, PRD.md가 추가·변경한 내용을 반영했다. 둘이 다른 곳은 `**차이:**`로, 문서에 정해진 내용이 없는 곳은 `미정`으로 적었다. 구성 요소 이름과 Variant는 doc/Design.md로 확인했다. 개인정보 형태의 예시값(이름, 휴대폰 번호, 신청 번호)은 옮기지 않았다.

## 요금제 목록

### 라우트
- /plans
  - 제안 라우트 (screens.md에 라우트 정의 없음, PRD가 그대로 사용)

### 구성 요소
- Header (Type=root): 제목 있음
- 목록 안내 영역 (신규): 제목 문구와 설명 문구 있음
  - **차이:** screens.md는 안내 문구만 있고, PRD는 저장한 요금제가 있을 때 "지난번에 확인한 요금제가 있어요" 문구를 이 영역에 추가한다. (F12, [가정])
- 최근 3개월 데이터 이용량 표시 (PRD 추가, F1)
  - **차이:** screens.md에 없고, PRD가 추가한다. 이용량과 제공량을 비교하는 전용 컴포넌트는 없다(Design.md). 구성 방식: 미정. 통화·문자는 비교하지 않는다.
- Card/Plan (State=default) × 3: 베이직, 스탠다드, 프리미엄
  - 각 카드: 월 요금, 데이터·통화·문자 제공량
  - 각 카드 내부 Button (Type=Secondary, Size=sm, State=Default): 문구 "자세히", 해당 요금제 상세로 이동
  - **차이:** 맞는 요금제 표시는 screens.md에 없고, PRD가 추가한다. (F2) 표시 방식: 미정
  - **차이:** 저장한 요금제의 카드에 Tag("저장함")를 붙이는 것은 screens.md에 없고, PRD가 추가한다. (F12, [가정])
- 설명: 모든 요금은 부가세 포함이라는 안내
- 하단 안내: 요금제를 선택하면 상세 내용을 확인할 수 있다는 안내

### 상태
- 기본: 요금제 카드 3개와 각 카드의 '자세히' 버튼을 표시한다.
- 저장 있음: "나중에 다시 확인"으로 저장한 요금제의 카드에 Tag("저장함")를 붙이고 안내 문구를 보여준다. (PRD, [가정])
  - **차이:** screens.md에는 이 상태가 없다.
- 로딩: 미정
- 빈: 미정
- 에러: 미정

### 이동
- 들어오는 곳:
  - 플로우 시작 지점 '진입' (이전 화면은 정의되어 있지 않다)
  - 요금제 상세의 뒤로 가기
- 나가는 곳:
  - '자세히' → 선택한 요금제의 요금제 상세

## 요금제 상세

### 라우트
- /plans/:planId
  - planId는 목록에서 선택한 요금제를 구분한다. 제안 라우트이다.

### 구성 요소
- Header (Type=default): 제목 있음, 내부 icon/arrowLeft(요금제 목록으로 돌아가기)
- 정보 영역 (신규): 선택한 요금제 이름, 월 요금, 부가세 포함·매월 정기 구독 표시 (예시 요금제 있음)
- 월 요금 절감액과 위약금 (PRD 추가, F3·F4)
  - **차이:** screens.md에 없고, PRD가 추가한다. 두 금액만 나란히 보여주고 회수 기간 같은 해석은 보여주지 않는다. Card/Price는 공개 Text 속성이 없고 크기가 고정되어 있어(Design.md) 문구를 바꿀 수 없으면 새 사양이 필요하다. 사용할 컴포넌트: 미정
- 섹션 제목 (신규): 제공 혜택, 구독 안내
- List/Row (Type=default) × 3: 제공 혜택 (데이터, 통화, 문자)
- 설명 (신규): 신청일부터 이용, 매월 같은 날짜 자동 결제 안내
  - 이 문구를 PRD 기준으로 유지할지: 미정 (PRD는 신청 완료 화면의 "다음 결제일", "매월 자동 결제" 문구만 뺀다고 하고, 이 화면은 언급하지 않는다. "구독" 용어를 "요금제 변경"으로 바꿀지도 열린 질문이다.)
- 하단 액션 3개 (세로 배치, Button xl): 변경 신청(Primary), 상담 요청(Secondary), 나중에 다시 확인(Secondary)
  - **차이:** screens.md는 구독 신청(Primary)과 뒤로 · 요금제 목록(Secondary) 2개이고, PRD는 변경 신청(Primary), 상담 요청(Secondary), 나중에 다시 확인(Secondary) 3개이다. 이 화면의 "뒤로" 버튼은 PRD 액션 3개에 없다. 헤더의 뒤로 가기(icon/arrowLeft)는 PRD가 바꾼다는 언급이 없다.
  - 버튼 사이 gap 8px, 하단 영역 높이 216px. Header와 하단 액션은 고정하고 본문만 세로 스크롤한다. (PRD 9장)
- 상담 요청 접수 후: "상담 요청이 접수되었어요" 안내 문구를 보여주고 상담 요청 버튼을 Disabled로 바꾼다. (F11, [가정]) 안내 문구가 놓이는 위치: 미정

### 상태
- 기본: 목록에서 선택한 요금제의 정보와 절감액·위약금을 표시한다.
  - **차이:** screens.md는 요금제 정보만 표시하고, PRD는 절감액·위약금을 추가한다.
- 상담 요청 접수됨: 같은 화면에 접수 안내가 나오고 상담 요청 버튼이 Disabled이다. (PRD, [가정])
  - **차이:** screens.md에는 이 상태가 없다.
- 나중에 다시 확인 저장됨: 요금제 하나와 저장 시각을 브라우저에만 저장한다. (F12, [가정]) 저장 직후 화면 표시와 이동: 미정
  - **차이:** screens.md에는 이 상태가 없다.
- 로딩: 미정
- 빈: 미정
- 에러: 미정

### 이동
- 들어오는 곳:
  - 요금제 목록의 '자세히'
  - 구독 신청의 취소
  - 구독 신청 헤더의 뒤로 가기
- 나가는 곳:
  - '변경 신청' → 구독 신청
  - 헤더의 뒤로 가기 → 요금제 목록
  - '상담 요청' → 이동 없음, 같은 화면에서 접수 (PRD, [가정])
  - '나중에 다시 확인' → 브라우저에 저장, 저장 후 이동 여부: 미정. 저장한 요금제는 요금제 목록에서 다시 보여준다.
  - **차이:** screens.md는 '뒤로 · 요금제 목록' 버튼도 요금제 목록으로 이동하지만, PRD의 액션 3개에는 이 버튼이 없다.

## 구독 신청

### 라우트
- /plans/:planId/subscribe
  - 제안 라우트이다.

### 구성 요소
- Header (Type=default): 제목 있음, 내부 icon/arrowLeft(요금제 상세로 돌아가기)
- 섹션 제목 (신규): 신청 내용, 신청자 정보
- List/Row (Type=default) × 3: 요금제, 월 요금(부가세 포함), 이용 시작일 (예시값 있음)
  - PRD의 "신청한 내용 기준" 표시 항목 변경 여부: 미정
- 입력 항목 이름 (신규): 이름, 휴대폰 번호
- Input (State=filled) × 2: 이름 입력, 휴대폰 번호 입력 (예시값 있음)
  - 이 입력란을 유지할지: 미정 (PRD 열린 질문: 고객이 식별된 것으로 보고 뺄지. 로그인이 없어 필요할 수 있다는 [가정])
- 설명 (신규): 신청 내용 확인 요청, 매월 자동 결제, 신청 결과를 입력한 번호로 안내
  - 이 문구를 PRD 기준으로 유지할지: 미정 (PRD는 신청 완료 화면의 자동 결제 문구만 뺀다고 한다.)
- 위약금 안내 영역 (PRD 추가, F7): 위약금 금액과 약정 남은 기간 등을 최종 완료 전에 안내한다.
  - **차이:** screens.md에 없고, PRD가 추가한다. "등"에 포함되는 항목과 사용할 컴포넌트: 미정
- 하단 액션 3개 (세로 배치, Button xl): 신청(Primary, 최종 완료), 상담 요청(Secondary), 취소(Secondary)
  - **차이:** screens.md는 신청(Primary)과 취소 · 요금제 상세(Secondary) 2개이고, PRD는 신청(Primary, 최종 완료), 상담 요청(Secondary), 취소(Secondary) 3개이다.
  - 버튼 사이 gap 8px, 하단 영역 높이 216px. Header와 하단 액션은 고정하고 본문만 세로 스크롤한다. (PRD 9장)
- 상담 요청 접수 후: 같은 화면에 "상담 요청이 접수되었어요" 안내가 나오고 상담 요청 버튼은 Disabled이다. (F11, [가정])

### 상태
- 기본: 선택한 요금제의 신청 내용, 신청자 입력 항목, 위약금·약정 남은 기간 안내를 표시한다. (screens.md 화면은 입력값이 채워진 상태로 제시)
  - **차이:** 위약금·약정 안내 영역은 PRD가 추가한다.
- 상담 요청 접수됨: 접수 안내가 나오고 상담 요청 버튼이 Disabled이다. (PRD, [가정])
  - **차이:** screens.md에는 이 상태가 없다.
- 로딩: 미정 (신청 처리 중 표시와 버튼 상태)
- 빈: 미정 (입력 전 화면과 필수 입력 조건)
- 에러: 미정 (입력 검증 조건, 오류 문구, 신청 실패 처리. PRD는 실제 변경 실패 처리를 범위에서 제외한다.)

### 이동
- 들어오는 곳:
  - 요금제 상세의 '변경 신청'
- 나가는 곳:
  - '신청'(최종 완료) → 신청 완료 (신청 접수, 실제 요금제 변경은 하지 않는다.)
  - '취소' → 요금제 상세
  - 헤더의 뒤로 가기 → 요금제 상세
  - '상담 요청' → 이동 없음, 같은 화면에서 접수 (PRD, [가정])

## 신청 완료

### 라우트
- /plans/:planId/subscribe/complete
  - 제안 라우트이다.

### 구성 요소
- Header (Type=root): 제목 있음
- icon/doneMark (내부 icon/check 포함)
- 완료 제목 (신규)
  - **차이:** screens.md는 "구독 신청이 완료됐어요" 취지이고, PRD는 "신청이 접수되었어요"로 안내한다. 요금제가 이미 바뀐 것으로 오해하지 않게 "변경되었어요"는 쓰지 않는다. 정확한 문구: 미정
- 설명 (신규): 신청 접수와 문자 안내 (예시 요금제 있음)
  - 문자 안내 문구를 PRD 기준으로 유지할지: 미정 (PRD에 언급 없음)
- 섹션 제목 (신규): 신청 내역
- List/Row (Type=default): 신청 내역
  - **차이:** screens.md는 6행(신청 번호, 요금제, 월 요금, 이용 시작일, 신청자, 휴대폰 번호, 모두 예시값 있음)이고, PRD는 변경 후 요금제, 월 요금, 위약금 안내 확인을 보여준다. 행 수와 각 행의 항목: 미정 (신청 번호, 신청자, 휴대폰 번호 행 유지 여부는 PRD가 정하지 않았고, 이용 시작일은 PRD의 "변경 적용 시점" 열린 질문과 연결된다.)
- (제외) 다음 결제 설명
  - **차이:** screens.md에는 다음 결제일과 매월 자동 결제 문구를 보여주는 설명 영역이 있고, PRD는 이 문구를 뺀다. 이 화면의 구성 요소에는 포함하지 않는다.
- Button (Type=Primary, Size=xl, State=Default): 문구 "완료", 플로우 종료. 이후 이동 화면은 정의되어 있지 않다.

### 상태
- 기본: 신청 접수 안내와 신청 내역을 표시한다. 번호·날짜·개인정보는 screens.md의 예시값이고 옮기지 않았다(예시값 있음).
  - **차이:** screens.md의 다음 결제 정보 표시는 PRD가 뺐다.
- 로딩: 미정
- 빈: 미정
- 에러: 미정

### 이동
- 들어오는 곳:
  - 구독 신청의 '신청'
- 나가는 곳:
  - '완료' → 플로우의 끝. 목적지 화면: 미정
