# screen-spec.md

기준: doc/screens.md를 바탕으로 PRD.md의 추가·변경분을 반영했다. 충돌하면 PRD를 따르고 `**차이:**`로 표시했다. 문서에 없거나 정해지지 않은 항목은 `미정`이다. 개인정보 형태의 예시값은 옮기지 않았다.

## 요금제 목록

### 라우트
- /plans

### 구성 요소
- Header (Type=root)
- 목록 안내 영역
  - **차이:** screens.md는 안내 문구만 있고, PRD는 저장한 요금제가 있으면 "지난번에 확인한 요금제가 있어요" 문구를 추가한다. (F12)
- 최근 3개월 데이터 이용량 표시
  - **차이:** screens.md에 없고, PRD가 추가한다. (F1) 통화·문자는 비교하지 않는다.
  - 이용량과 제공량을 비교하는 전용 컴포넌트가 Design.md에 없다. 구성 방식은 미정이다. (기존 컴포넌트로 구성하거나 새 사양 필요)
- Card/Plan (State=default) x 3: 베이직, 스탠다드, 프리미엄
  - 각 카드: 월 요금, 데이터·통화·문자 제공량
  - **차이:** screens.md는 제공량 표시만 있고, PRD는 카드에서 이용량과 제공량을 비교할 수 있게 한다. (F1)
  - **차이:** screens.md에 없고, PRD는 "맞는 요금제"를 표시한다. (F2) 표시 방식(Chip, Tag 등)은 미정이다.
  - 저장한 요금제 카드에 Tag("저장함")를 붙인다.
    - **차이:** screens.md에 없고, PRD가 추가한다. (F12)
  - 각 카드 내부 Button (Type=Secondary, Size=sm, State=Default): "자세히"
- 설명: 부가세 포함 안내
- 하단 안내: 요금제 선택 안내

### 상태
- 기본: 요금제 카드 3개와 각 카드의 "자세히" 버튼을 표시한다.
- 저장함: 저장한 요금제 카드에 Tag("저장함")와 목록 안내 문구가 나온다. (PRD, 가정)
  - **차이:** screens.md에 없고, PRD가 추가한다.
  - 저장 삭제 방법과 유효기간은 미정이다.
- 로딩: 미정
- 빈: 미정
- 에러: 미정

### 이동
- 들어오는 곳:
  - 플로우 시작 지점(진입). 이전 화면은 미정이다.
  - 요금제 상세의 뒤로 가기 (헤더)
- 나가는 곳:
  - "자세히" -> 요금제 상세

## 요금제 상세

### 라우트
- /plans/:planId
  - planId는 목록에서 선택한 요금제를 구분한다.

### 구성 요소
- Header (Type=default), 내부 icon/arrowLeft (요금제 목록으로 돌아가기)
- 정보 영역: 선택한 요금제 이름과 월 요금 (예시 요금제 데이터)
  - 부가세 포함 안내
  - **차이:** screens.md는 "매월 정기 구독" 문구가 있고, PRD는 이 문구의 처리를 정하지 않았다. 유지·삭제 여부는 미정이다.
- 맞는 요금제, 월 요금 절감액, 위약금을 한 화면에서 표시
  - **차이:** screens.md에 없고, PRD가 추가한다. (F2, F3) 절감액과 위약금은 두 금액만 나란히 보여주고 회수 기간 같은 해석은 쓰지 않는다. (F4)
  - Card/Price는 공개 Text 속성이 없고 크기가 고정이다. 이 화면에 쓸 컴포넌트는 미정이다. (새 사양 필요 여부 미정)
  - 위약금 강조에 `text/error`는 쓰지 않는다.
- 섹션 제목: 제공 혜택, 구독 안내
- List/Row (Type=default) x 3: 데이터, 통화, 문자
- 설명: 이용 시작과 자동 결제 안내
  - **차이:** screens.md는 "매월 같은 날짜에 자동 결제" 안내가 있고, PRD는 이 문구의 처리를 정하지 않았다. 유지·삭제 여부는 미정이다.
- 하단 액션 3개 (세로 배치): 변경 신청(Primary), 상담 요청(Secondary), 나중에 다시 확인(Secondary)
  - Button xl 3개, gap 8px, 하단 영역 216px (Design.md에 없는 별도 사양)
  - **차이:** screens.md는 구독 신청(Primary)과 "뒤로 · 요금제 목록"(Secondary) 2개이고, PRD는 3개이다.
  - **차이:** "뒤로 · 요금제 목록" 버튼의 유지 여부는 PRD에 명시가 없어 미정이다. (헤더 뒤로 가기는 유지)
  - **차이:** screens.md의 버튼 문구 "구독 신청"은 PRD에서 "변경 신청"이다. 용어 "구독"을 "요금제 변경"으로 바꿀지는 PRD 열린 질문이라 다른 문구는 screens.md를 따른다.
- 스크롤: Header와 하단 액션은 고정하고 본문만 스크롤한다. 본문 가용 높이는 572px이다. (PRD 결정)
  - **차이:** screens.md에 없고, PRD가 추가한다.

### 상태
- 기본: 선택한 요금제의 정보를 표시한다.
- 상담 요청 접수 후: 같은 화면에 "상담 요청이 접수되었어요" 안내가 나오고 상담 요청 버튼이 Disabled(`fill/disabled`)가 된다. (F11, 가정)
  - **차이:** screens.md에 없고, PRD가 추가한다. 안내 문구의 정확한 내용은 미정이다.
- 나중에 다시 확인 저장 후: 요금제 하나와 저장 시각을 브라우저에 저장한다. (F12, 가정) 저장 직후 화면 표시는 미정이다.
  - **차이:** screens.md에 없고, PRD가 추가한다.
- 로딩: 미정
- 빈: 미정
- 에러: 미정

### 이동
- 들어오는 곳:
  - 요금제 목록의 "자세히"
  - 구독 신청의 취소 버튼
  - 구독 신청의 헤더 뒤로 가기
- 나가는 곳:
  - "변경 신청" -> 구독 신청
  - 헤더 뒤로 가기 -> 요금제 목록
  - "뒤로 · 요금제 목록" -> 요금제 목록 (버튼 유지 여부 미정)
  - "상담 요청", "나중에 다시 확인" -> 이동 없음, 같은 화면에서 처리

## 구독 신청

### 라우트
- /plans/:planId/subscribe

### 구성 요소
- Header (Type=default), 내부 icon/arrowLeft (요금제 상세로 돌아가기)
- 섹션 제목: 신청 내용, 신청자 정보
- List/Row (Type=default) x 3: 요금제, 월 요금(부가세 포함), 이용 시작일 (예시값 있음)
  - **차이:** PRD는 이 행들의 유지 여부를 정하지 않았다. 이용 시작일 유지 여부는 미정이다.
- 위약금 금액과 약정 남은 기간 등 안내 영역
  - **차이:** screens.md에 없고, PRD가 추가한다. (F7) 최종 완료(신청 버튼)보다 앞에 둔다. 컴포넌트와 구성은 미정이다.
  - 약정 구조(항목별인지 하나인지)가 정해지지 않아 약정 남은 기간 표시 방식은 미정이다.
- 입력 항목 이름 레이블: 이름, 휴대폰 번호
- Input (State=filled) x 2: 이름, 휴대폰 번호 (예시값 있음, 옮기지 않음)
  - **차이:** PRD는 입력란 유지 여부를 열린 질문으로 남겼다. 유지 여부는 미정이다. 예시 데이터는 더미값만 쓴다. (PRD 가정)
- 설명: 신청 내용 확인 및 자동 결제 안내
  - **차이:** screens.md는 "신청일부터 매월 자동 결제" 안내가 있고, PRD는 이 화면의 문구를 정하지 않았다. (신청 완료 화면에서는 자동 결제 문구를 뺀다.) 유지·삭제 여부는 미정이다.
- 하단 액션 3개 (세로 배치): 신청(Primary, 최종 완료), 상담 요청(Secondary), 취소(Secondary)
  - Button xl 3개, gap 8px, 하단 영역 216px
  - **차이:** screens.md는 신청(Primary)과 "취소 · 요금제 상세"(Secondary) 2개이고, PRD는 3개이다. 상담 요청이 추가되고 취소 문구는 "취소"이다.
- 스크롤: Header와 하단 액션은 고정하고 본문만 스크롤한다. (PRD 결정)
  - **차이:** screens.md에 없고, PRD가 추가한다.

### 상태
- 기본: 신청 내용, 위약금·약정 안내, 신청자 입력 항목을 표시한다. screens.md 화면은 입력이 채워진 상태로 제시되어 있다.
- 상담 요청 접수 후: 같은 화면에 접수 안내가 나오고 상담 요청 버튼이 Disabled가 된다. (F11, 가정)
  - **차이:** screens.md에 없고, PRD가 추가한다. 안내 문구는 미정이다.
- 로딩: 미정 (신청 처리 중 표시와 버튼 상태)
- 빈: 미정 (입력 전 화면과 필수 입력 조건)
- 에러: 미정 (입력 검증 조건, 오류 문구, 신청 실패 처리)
  - Input 검증 오류가 필요하면 `text/error`와 Input State=caution을 쓴다. (Design.md)

### 이동
- 들어오는 곳:
  - 요금제 상세의 "변경 신청"
- 나가는 곳:
  - "신청" -> 신청 완료 (신청을 접수한다. 실제 요금제 변경은 하지 않는다.)
  - "취소" -> 요금제 상세
  - 헤더 뒤로 가기 -> 요금제 상세
  - "상담 요청" -> 이동 없음, 같은 화면에서 처리

## 신청 완료

### 라우트
- /plans/:planId/subscribe/complete

### 구성 요소
- Header (Type=root)
- icon/doneMark (내부 icon/check 포함)
- 완료 제목
  - **차이:** screens.md는 "구독 신청이 완료됐어요"이고, PRD는 "신청이 접수되었어요"로 안내한다. "변경되었어요"는 쓰지 않는다. (F9)
- 설명
  - **차이:** screens.md의 설명(접수 안내와 문자 발송 안내)을 PRD가 바꾸는지는 명시가 없다. 문자 안내 유지 여부는 미정이다. 접수만 말하고 변경 완료로 읽히는 표현은 쓰지 않는다.
- 섹션 제목: 신청 내역
- List/Row (Type=default): 신청 내역
  - **차이:** screens.md는 6행(신청 번호, 요금제, 월 요금, 이용 시작일, 신청자, 휴대폰 번호)이다. PRD는 신청 내역을 변경 후 요금제, 월 요금, 위약금 안내 확인으로 정한다. 행 수와 구성은 PRD 기준이며, 나머지 행(신청 번호, 이용 시작일, 신청자, 휴대폰 번호)의 유지 여부는 미정이다. screens.md의 예시값은 옮기지 않았다.
- 다음 결제일, 매월 자동 결제 설명
  - **차이:** screens.md에 있고, PRD는 이 문구를 뺀다. 결과에는 넣지 않는다.
  - 변경 적용 시점 표시 여부는 미정이다.
- Button (Type=Primary, Size=xl, State=Default): "완료"

### 상태
- 기본: 신청 접수 안내와 신청 내역을 표시한다. 번호·날짜·개인정보 형태의 값은 screens.md의 예시값이며 옮기지 않았다.
- 로딩: 미정
- 빈: 미정
- 에러: 미정

### 이동
- 들어오는 곳:
  - 구독 신청의 "신청"
- 나가는 곳:
  - "완료" -> 플로우 종료. 이동할 화면은 미정이다.
