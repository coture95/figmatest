# 4단계 전 사람 결정 (사용자가 직접 선택)

screen-spec.md와 03-token-map.md의 '미정'·'토큰 없음' 중 구현에 걸리는 항목의 결정이다. 여기에 없는 '미정'은 임의로 정하지 말고 멈추고 보고한다. PRD와 충돌하면 PRD가 우선한다.

## 구독 신청 (/plans/[planId]/subscribe)
- 이름·휴대폰 번호 입력란: **만들지 않는다.** 고객이 이미 식별된 것으로 본다.
- 이용 시작일 행: 만들지 않는다.
- 따라서 입력 검증 오류(Input 검증, `text/error`), 필수 입력 조건은 구현하지 않는다.
- 화면은 신청 내용 확인 + 위약금·약정 남은 기간 안내 + 하단 버튼 3개(신청 Primary, 상담 요청 Secondary, 취소 Secondary)로 구성한다.

## 신청 완료 (/plans/[planId]/subscribe/complete)
- 신청 내역은 3행만: 변경 후 요금제, 월 요금, 위약금 안내 확인.
- 문자 발송 안내 문구, 신청 번호·신청자·휴대폰 번호 행은 만들지 않는다.
- 제목은 "신청이 접수되었어요". "변경되었어요", "다음 결제일", "매월 자동 결제"는 쓰지 않는다.
- "완료" 버튼은 `/plans`로 이동한다.

## 비교·금액 표시, 예외 상태
- 이용량 비교, 맞는 요금제, 절감액·위약금 표시는 Design.md의 기존 컴포넌트(Card/Plan, List/Row, Tag 등)를 조합해 만든다. 새 컴포넌트 사양은 만들지 않는다.
- 로딩·빈·에러 상태는 만들지 않는다. (PRD 제외 범위: 예외 상황. 예시 데이터라 항상 값이 있다.)

## '토큰 없음' 항목
- 크기(하단 3버튼 영역 216px 등)는 Design.md 값을 그대로 쓴다. width/height는 G2 검사 대상이 아니다.
- 글자 크기는 `doc/tokens.json` 목록 안의 값 중 Design.md가 지정한 값을 쓴다.
- 그림자는 `effect/shadow-subtle`, List/Row 레이블 색은 `text/secondary`, Card/Plan 배경은 `bg/surface`.

## 그 밖
- 예시 데이터: 요금제 3개(베이직 4,900원/3GB, 스탠다드 9,900원/10GB, 프리미엄 19,900원/30GB). 고객 이름은 "테스트 고객"만. 전화번호는 화면에 쓰지 않는다.
- 맞는 요금제: 최근 3개월 중 가장 많이 쓴 달의 이용량을 제공량이 넘지 않는 가장 저렴한 요금제(PRD [가정]). 예시 이용량은 이 계산 결과가 한 요금제로 정해지고 30GB를 넘지 않게 정한다.

## 추가 결정 (4단계 1차 중단 후, 사용자가 직접 선택)
- 상담 요청 접수 후: 버튼 위에 "상담 요청이 접수되었어요"를 `text/secondary`, 14px(body-small) 한 줄로 표시한다. Disabled 버튼은 배경 `fill/disabled`, 글자 `text/on-disabled`, 글자 스타일 body/medium.
- "나중에 다시 확인" 저장 직후: 상세 화면에 아무 표시도 추가하지 않고 저장만 한다. 목록에서 Tag("저장함")와 "지난번에 확인한 요금제가 있어요" 안내로 확인한다. (PRD에 저장 직후 표시가 없다.)
- 요금제 상세의 "매월 정기 구독", "매월 같은 날짜에 자동 결제" 문구는 만들지 않는다.
- 글자 스타일: 섹션 제목·완료 제목은 24px(`font-size/heading-h3`), 목록 하단 안내는 13px(`font-size/caption`). 목록 안내 영역에서 기본 안내와 "지난번에 확인한 요금제가 있어요" 사이 간격은 `spacing/16`.
- Figma: `get_design_context`를 읽어도 된다. 호출할 때 `skillNames`에 `resource:figma-design-to-code`를 넣고, 스크린샷을 함께 요청해 시각 기준으로 쓴다. 응답 코드는 프로토타입으로 보고 프로젝트 스택(Next, Tailwind)과 토큰에 맞게 바꾼다. 절대 좌표는 flex/grid로 바꾸고, 임시 Figma 에셋 URL을 코드에 남기지 않는다.

## 5단계 사람 승인 때의 결정 (사용자가 직접 선택)
- **승인:** 5단계 결과를 승인한다. 아래 수정 2건을 반영하면 완료.
- **통화·문자 제공량:** "기본 제공" 대신 `doc/screens.md`의 요금제별 값(분·건수)으로 복원한다. 목록 카드와 상세 모두. 주석의 `[문서에 없음]`도 맞게 고친다.
- **목록 하단 안내 문구:** 코드에서 정한 문구 대신 `doc/screens.md`의 하단 안내 문구로 복원한다. 주석도 맞게 고친다.
- **생략 승인(변경 없음):** 상세의 "구독 안내" 섹션 생략, 구독 신청의 자동 결제 문구 생략, 상세의 "뒤로 · 요금제 목록" 버튼 없음(헤더 뒤로 가기로 목록에 돌아간다).

## 완료 후 변경 요청 (사용자가 직접 요청, 이전 결정과 PRD F11·F12보다 우선)
- **"나중에 다시 확인"**: 누르면 지금처럼 저장(요금제와 저장 시각, 브라우저)한 뒤 **이전 페이지로 이동**한다. 이전 페이지 = 브라우저 뒤로 가기(`router.back()`). 이동 기록이 없으면 `/plans`로 보낸다. 저장 직후 화면 표시는 없다.
- **"상담 요청"**: 누르면 버튼 위 한 줄 안내 대신 **팝업(모달)** 을 띄운다. 팝업 문구는 "상담 요청이 접수되었어요", 버튼은 "확인" 1개. 확인을 누르면 팝업을 닫고 **이전 페이지로 이동**한다(같은 규칙: 뒤로 가기, 기록이 없으면 `/plans`).
- 따라서 접수 후 같은 화면의 한 줄 안내와 Disabled 상담 버튼 상태는 쓰지 않는다. 이 변경은 요금제 상세와 구독 신청 화면 양쪽의 상담 요청 버튼(공용 컴포넌트)에 적용한다.
- 팝업은 Design.md에 컴포넌트가 없다. 기존 토큰만으로 만든다: 흰 배경 `bg-surface`, 모서리 radius 16, 본문 글자 `text-primary`, 확인 버튼은 Primary 버튼 스타일 재사용, 뒤 배경 딤은 알파 0.1 검정만 허용(G2). 화면 중앙, 키보드(Esc)·포커스 접근성은 기본만.
- G3·G4(금지 문구, 안내 순서)는 그대로 지킨다.

## Supabase DB (사용자가 직접 요청·선택, PRD §4의 "브라우저에만 저장"보다 우선)
- 저장 범위: `plans`(요금제 3개 시드), `change_requests`(변경 신청), `consult_requests`(상담 요청), `saved_plans`(나중에 다시 확인). 이용량·약정·위약금 등 고객 예시 데이터는 코드에 그대로 둔다.
- 고객 구분: 브라우저가 만든 익명 UUID(`client_id`). 이름·전화번호 등 개인정보 컬럼은 만들지 않는다.
- 보안: 모든 테이블 RLS 켬. 브라우저(anon 키)는 `plans` 읽기와 신청·상담·저장 insert만. 신청·상담·저장 읽기는 서버(`SUPABASE_SERVICE_ROLE_KEY`)에서만. service role 키는 브라우저 코드에 쓰지 않는다.
- 실행: `supabase/migrations/*.sql`을 사용자가 Supabase SQL Editor에서 직접 실행한다. 앱 코드 연결은 별도 요청이 있을 때 한다.
