## 1. 유저 스토리 (PRD §5)

고객 A는 가상 인물이다.

1. 고객 A는 자신에게 맞는 요금제를 찾기 위해 최근 3개월 실제 이용량과 요금제별 제공량을 비교해 본다.
2. 고객 A는 바꿀지 판단하기 위해 맞는 요금제, 월 요금 절감액, 위약금을 한 화면에서 한꺼번에 확인한다.
3. 고객 A는 요금제를 바꾸기 위해 변경 신청을 하고, 최종 완료 전에 위약금 금액과 약정 남은 기간 안내를 확인한다.
4. 위약금이 부담스러운 고객 A는 확신을 얻기 위해 최종 완료 대신 상담을 요청하거나 신청을 취소한다.
5. 당장 결정하지 못한 고객 A는 나중에 다시 보기 위해 지금 본 내용을 저장해 둔다.

## 4. 비즈니스 규칙·디자인 제약 중 구현에 직접 영향

| 항목 | 내용 |
|---|---|
| 맞는 요금제 | 3개월 중 가장 많이 쓴 달의 이용량을 제공량이 넘지 않는 가장 저렴한 요금제 (최댓값 기준) **[가정]** |
| 위약금 | 가입 초기 혜택 환수 + 단말대금 지원 환수 + 요금할인 반환. 공식 없이 예시 데이터에 세 금액을 넣고 합계만 더함 **[가정]** |
| 고객 데이터 | 예시 데이터 사용. 더미값만 사용 ("테스트 고객", "010-0000-0000") **[가정]** |
| 고객 식별 | 식별된 것으로 보고 상담 요청에서 연락처를 받지 않음 **[가정]** |
| 하단 버튼 | Button xl 3개 세로, 맨 위 Primary, 나머지 Secondary, gap 8px, 하단 영역 216px |
| 스크롤 | Header와 하단 액션 고정, 본문만 스크롤. 본문 가용 높이 572px (844-56-216) |
| 접수 후 상태 | Button Disabled(`fill/disabled`), 레이블 `body/medium` |
| 저장 표시 | Tag("저장함"). Tag에 선택·실행 동작을 주지 않음 |
| 색 | `text/error`는 Input 검증 오류용. 위약금 강조에 쓰지 않음 |
| 비교 표현·Card/Price | 이용량-제공량 비교 전용 컴포넌트 없음. Card/Price는 문구 변경 불가 시 새 사양 필요 |

### 제외 범위 (만들지 않는다)
- 로그인·본인인증
- 실제 요금제 변경 처리와 변경 실패 처리
- 위약금 계산 공식, 실제 고객 데이터 연동
- 상담 처리(상담원 화면)
- 예외 상황 (약정 없음, 이용량 많은 고객, 이미 최적인 고객, 이용량 조회 실패). 예시 데이터에서 이 경우를 피한다.
- 위약금 회수 기간 등 금액 해석 표시
- 4개 화면 외 새 화면 **[가정]**

## 5. [가정]·열린 질문 중 구현에 영향을 주는 것

구현자가 임의로 정하지 않는다. 가정은 PRD 기본값으로 진행하되 확정은 아니다.

| 항목 | 상태 | 구현 영향 |
|---|---|---|
| 신청자 정보(이름, 휴대폰 번호) 입력 유지 여부 | 미정 | 화면 3의 Input 2개를 둘지 결정되지 않음. 로그인이 없어 필요할 수 있다는 가정만 있음 |
| screens.md의 개인정보 형태 예시값 | 사용 금지 | 더미값만 사용 |
| 신청 완료 화면의 변경 적용 시점 표시 | 미정 | 넣을지, 언제인지 정해지지 않음. 임의로 넣지 않는다 |
| 상담 요청 방식(화면·입력 없이 접수) | 가정 | 접수 안내 문구의 정확한 내용은 미정 |
| "충분히 커버"의 수치 기준 | 가정(최댓값) | 여유 비율 여부 미정. 개발은 최댓값 기준 |
| 나중에 다시 확인 (Tag로 재표시) | 가정 | 저장 삭제 방법, 유효기간 미정 |
| 용어 "구독" → "요금제 변경" 변경 여부 | 미정 | 화면 이름·문구는 우선 screens.md를 따름 |
| 위약금 변경 대상 요금제별 차이 | 미정 | 이번에는 예시 금액 합계만 사용 |
| 약정 구조 (항목별 약정 vs 하나의 약정) | 미정 | 약정 남은 기간 표시 방식에 영향 |
| 고객 구분 기준 | 미정 | 세 액션은 선택지로만 제공, 고객 분기 로직 없음 |
| 성공 지표 | 미정 | 구현 영향 없음 |
| 로딩·빈·에러 상태 | 미정 | screens.md에 정의 없음. 만들지 않거나 별도 확인 필요 |
| 신청 완료 화면의 "완료" 버튼 이동 | 미정 | screens.md상 플로우 종료, 이동 화면 정의 없음 |
| PRD와 screens.md 충돌 시 | PRD 우선 | 예: screens.md의 "다음 결제일", 정기 구독 문구, 뒤로 버튼 구성은 PRD 변경분 우선 |

### screens.md 중 PRD와 충돌하거나 정리가 필요한 문구
- 화면 2의 "정기 구독 안내", "매월 같은 날짜에 자동 결제" 문구: PRD 취지(요금제 변경 신청 접수)와 맞지 않음. 처리 방식은 PRD에 명시 없음 → 미정
- 화면 2의 버튼 "구독 신청", "뒤로 · 요금제 목록": PRD는 하단 액션 3개로 변경. "뒤로 · 요금제 목록" 버튼의 유지 여부는 PRD에 명시 없음 → 미정 (헤더 뒤로 가기는 유지)
- 화면 4의 "완료 제목: 구독 신청이 완료됐어요": PRD는 "신청이 접수되었어요"로 바꿈 (규칙 B)
